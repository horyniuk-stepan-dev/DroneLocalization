## 🔴 КРИТИЧНІ — прямі причини нестабільності

### 1. Розсинхрон нумерації кадрів: діалог = кадри відео, БД = слоти `//frame_step`
**Найімовірніша головна причина.**

- `DatabaseBuilder`: індекс БД = `video_frame // frame_step`, `frame_step` за замовчуванням **30** (`config/config.py:43`), `num_frames = ceil(total/step)` (`database_builder.py:114,372`).
- `CalibrationDialog` дає `frame_id` = номер кадру **того відео, яке завантажив користувач** (`calibration_dialog.py:454-471, 739`). Жодної конвертації.
- Збіг є ТІЛЬКИ якщо завантажено `<db>_keypoints.mp4` (1 кадр = 1 слот БД). Якщо завантажено оригінальне відео польоту — якір «кадр 4500» шукається у слоті 4500 (= кадр відео 135000!) або:
- `calibration_propagation_worker.py:114`: `anchors = [a for a in all_anchors if a.frame_id < num_frames]` — якорі за межами **мовчки викидаються** (тільки лог). Середина/кінець маршруту зникають, граф пінується неправильно → результат «то працює, то божевільний».

**Фікс:**
1. Записувати `frame_step` у metadata БД (зараз не зберігається).
2. У діалозі автозавантажувати `<db>_keypoints.mp4`; при завантаженні іншого відео порівнювати кількість кадрів з `get_num_frames()`: якщо ≈ `num_frames*step` — ділити індекс на step, інакше — блокувати з поясненням.
3. У воркері: якщо якір відфільтровано — `error.emit`, а не тихий лог.

### 2. PCHIP-інтерполяція якорів руйнує Y-віддзеркалення (det<0)
- Після фіксу «БАГ 2» у `calibration_mixin.py` якірні матриці **завжди** full affine з `det < 0` (px Y↓ → metric Y↑; коментар у `transformations.py:75` це підтверджує).
- Але `_rebuild_interpolators`/`_get_interpolated_matrix` (`multi_anchor_calibration.py:127-214`) використовують 4-DoF `decompose_affine`/`compose_affine` (`affine_utils.py:13-40`), які **не кодують відбиття**: реконструйована матриця завжди має `det > 0`.
- Наслідок: між якорями Y-складова дзеркалиться — похибка ≈ `2·s·y` (для s=0.05 м/px, y=540 → **~54 м**), а точно на якорі гілка «exact hit» повертає правильний результат → різкі стрибки біля якорів.
- Зараз `get_metric_position` ніде не викликається в live-пайплайні (все йде через `frame_affine` з HDF5), тож це «міна», але вона спрацює при будь-якому фолбеку/тесті без пропагації.

**Додатково у тому ж місці:**
- Параметризація навколо пікселя (0,0), а не центру кадру: при зміні кута між якорями центр «гойдається» навколо лівого-верхнього кута (PoseGraphOptimizer робить правильно — навколо центру, `_affine_to_state`).
- `PchipInterpolator(..., extrapolate=True)` (`:202`) — кубічна екстраполяція за межами якорів розлітається. Треба clamp до крайніх якорів.

**Фікс:** перейти на `decompose_affine_5dof`/`compose_affine_5dof` зі `sign` з `det`, декомпозицію робити відносно центру кадру, `extrapolate=False` + clamp.

### 3. Недетермінований фіт якоря: RANSAC з порогом у МЕТРАХ на 4–6 точках
- `calibration_mixin.py:118` → `estimate_affine(pts_px, pts_metric)` → `cv2.estimateAffine2D(..., RANSAC, ransacReprojThreshold=3.0)` (`transformations.py:286`).
- Поріг інтерпретується в одиницях призначення = **метрах** (ще й меркаторських). Похибка кліку+GPS орієнтира ≈ 1–3 м — точки на межі порогу «блимають» inlier/outlier між запусками (RNG OpenCV) → **ті самі точки дають різні матриці** → різний RMSE → «нестабільний крок калібрації» буквально.
- RANSAC на 4–6 точках взагалі не має сенсу (мінімальна вибірка 3).

**Фікс:** для ≤6 точок — звичайний LSQ по всіх точках (`cv2.estimateAffine2D(..., method=0)` або numpy lstsq) + показ залишків по точках; RANSAC-маску, якщо лишати, то використовувати (зараз ігнорується, `inliers_count = len(points)`, `calibration_mixin.py:225`).

### 4. Якір на порожньому слоті = мовчки проігнорований якір
- Keyframe selection увімкнений за замовчуванням (`keyframe_min_translation_px=15`), непорушні кадри лишають порожні слоти (`kp_counts=0` → `get_local_features` кидає ValueError, `database_loader.py:284-286`).
- `fix_node(anchor.frame_id, ...)` (`pose_graph_optimizer.py:81`) створює вузол, навіть якщо у нього немає фіч/ребер → **ізольований фіксований вузол**: BFS з нього нікуди не йде, обмежень не додає. Якір «зник» без попередження.

**Фікс:** перед `fix_node` перевіряти наявність фіч; snap до найближчого keyframe через `metadata/frame_index_map` (вже зберігається, але не використовується) з перерахунком через temporal H.

## 🟠 СЕРЙОЗНІ

### 5. Web Mercator: усі «метри» розтягнуті в ~1.4–1.5×
- Дефолт `projection.default_mode = WEB_MERCATOR` (EPSG:3857, `coordinates.py:53`). На широті 47–50° масштаб = 1/cos(lat) ≈ 1.47–1.56.
- RMSE якоря, пороги 3м/5м, `frame_gps`-відстані — у «псевдометрах», а diagnostics по Хаверсину (`calibration_mixin.py:258`) — у справжніх. Значення не збігаються між собою у ~1.5 раза.
**Фікс:** UTM за замовчуванням, або корекція `cos(lat)` для всіх метрик/порогів.

### 6. Стан-залежні ваги у резидуалах оптимізатора
- `pose_graph_optimizer.py:308-309`: `w_trans = w / sx_i`, де `sx_i` — оптимізована змінна. Оптимізатор може зменшувати трансляційні резидуали, роздуваючи масштаб (частково стримується scale-резидуалом, але зміщує розв'язок).
**Фікс:** нормалізувати фіксованим масштабом (з BFS-ініціалізації або медіани якорів).

### 7. Розрив temporal-ланцюга на гепах keyframe selection
- `calibration_propagation_worker.py:248`: ребро будується лише якщо `(i - last_success_id) <= max_skip_frames` (**3 слоти** = 90 кадрів відео при step=30). Hover/повільні ділянки → геп більший → ланцюг рветься, сегмент тримається тільки на loop closures; без якоря в сегменті — випадає й заповнюється лінійною інтерполяцією через пів маршруту.
**Фікс:** з'єднувати послідовні кадри-з-фічами незалежно від відстані у слотах (з валідацією матчу), або рахувати пропущені keyframes, а не слоти.

### 8. `ratio_threshold`: конфіг 0.85 «перекриває» фікс 0.75
- `matcher.py:109` — дефолт 0.75 (виправлення «БАГ 4»), але `config.py:70` має `ratio_threshold: 0.85`, і get_cfg бере його. Фікс фактично не діє → більше сміттєвих матчів у ребрах графа.
