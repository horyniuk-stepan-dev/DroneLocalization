# План покращення калібрації v2 — м'які якорі, розумні гейти, GT-валідація

Дата: 2026-07-09. Продовження [POSE_GRAPH_IMPROVEMENT_PLAN.md](POSE_GRAPH_IMPROVEMENT_PLAN.md)
(той план виконано повністю: бенчмарк-каркас, діагностика, гейти ребер, two-stage prune,
аналітичний якобіан, warm start).

Контекст цього плану — результати наскрізного тесту симулятор↔локалізатор (2026-07-09):

- Симулятор генерує GT-якорі v2.3 (слот-вирівнювання з DatabaseBuilder, 5 точок, LSQ,
  якорі на кожному слоті розворотів + straight_fill, heading-hold).
- Хибні loop closures ловляться гейтами лише після ручного тюнінгу під місію
  (`loop_closure_min_frame_gap=30` виведено вручну з геометрії прольоту).
- Кути/масштаби гейтів (15°/1.3) валідні лише для heading-hold-місій.
- Пропущені кадри інтерполюються лінійно → «сходинки» на дугах.
- GT (телеметрія симулятора) досі не використовується для числової оцінки якості.

## Успадковані інваріанти (НЕ ЧІПАТИ)

1. Ваги трансляції `w/sx_i`, `w/sy_i`; чистий L2 як базовий режим; 6-DoF ребра;
   `w_reg = 200·cx` — див. попередній план, там пояснено, чому їх ламати не можна.
2. **Урок soft_l1**: глобальний robust loss глушить саме loop closures (у них
   природно великі резидуали). Будь-яка робастність — тільки класо-відносна
   (пороги/ваги відносно інших spatial-ребер), тільки за прапорцем, тільки через бенчмарк.
3. Все нове — за конфіг-прапорцем, дефолт = поточна поведінка. Кожен крок проходить
   `benchmark_propagation.py` + контракт-тести до мержа.

## Етап 0 — GT-валідатор проти телеметрії симулятора (нульовий ризик, робити першим)

Зараз якість пропагації оцінюється оком по карті. Симулятор уже пише `telemetry.csv`
(GT-позиція кожні N кадрів) — цього досить для точної метрики.

### 0.1 `scripts/validate_vs_telemetry.py`
Вхід: `database.h5` (frame_gps/frame_affine після пропагації) + `telemetry.csv` + frame_step.
- Інтерполяція GT-позиції на кожен слот (телеметрія щільніша за слоти — лінійної досить).
- GT local → Mercator → порівняння з центром кадру за `frame_affine`.
- Метрики: median/p95/max err (м) загалом і в розрізах: **прямі / дуги розворотів /
  ±3 слоти від якоря / середини прольотів між якорями**. Розрізи — головна цінність:
  вони показують, ЩО саме дає похибку.
- Вихід: JSON поряд із базою + короткий текстовий звіт. Інтеграція в
  `benchmark_propagation.py` як додаткове джерело істини.

### 0.2 GT-експорт із симулятора (точніше за телеметрію)
CalibrationLogger вже рахує GT-афінну для КОЖНОГО слота (кандидати) — додати
`--gt-file ground_truth.json`: скидати всі кандидати (slot → affine), а не лише вибрані
якорі. Валідатор тоді порівнює не тільки центр, а й кут/масштаб по кожному слоту.
Це закриває давній пункт «GT-експорт» зі старого плану однією годиною роботи.

**Гейт:** нема (read-only інструмент). Далі всі етапи міряються ним.

## Етап 1 — М'які якорі + LOO-перевірка (найбільший приріст для реальних даних)

Зараз якорі — жорстко фіксовані вузли (`fix_node`): помилковий ручний якір
(реальні мають RMSE 5–10 м) гне граф, і його не можна «переголосувати».

### 1.1 Якір як унарний фактор
- `optimizer.add_anchor(fid, affine, sigma_m)`: 5-вектор резидуалів
  `w_a · (state − state_anchor)`, `w_a = anchor_base_w / max(sigma_m, sigma_floor)`.
  σ береться з `rmse_m` якоря; GT-якорі симулятора (σ≈0) капаються до `sigma_floor`
  (напр. 0.05 м) → практично жорсткі, поведінка на сим-даних не змінюється.
- Local Origin і BFS-ініціалізація працюють як зараз (якір лишається стартом BFS).
- Конфіг: `graph_optimization.soft_anchors: bool = False`,
  `anchor_base_w`, `anchor_sigma_floor_m`. Мертвий ключ `anchor_weight` у
  `config/graph.py` — підключити сюди або видалити.

### 1.2 LOO-валідація якорів (до оптимізації, read-only)
Для кожного якоря: прибрати його, зпрогнозувати його стан temporal-ланцюгом від сусідніх
якорів, порівняти. Розбіжність > поріг → `quality_flag='warning'` у звіті пропагації
(«Якір #240 конфліктує з ланцюгом на 38 м — перевірте точки»). Доповнює наявний
anchor-stress (той працює лише постфактум).

**Гейт:** бенчмарк на сим-даних ідентичний (σ→floor = жорсткі); синтетичний тест
з навмисно кривим якорем: median_err із soft_anchors краще ніж без.

## Етап 2 — Автогейти замикань з геометрії місії (прибрати ручний тюнінг)

### 2.1 Авто `min_frame_gap`
З temporal-ребер уже відомий медіанний рух за слот у px (`median |dtx,dty|`).
Мінімальний геп без фізичного перекриття: `gap_min = ceil(k_overlap · frame_diag_px /
median_disp_px)`. Рахувати після Phase 1, застосовувати в Phase 2 замість константи.
Конфіг: `loop_closure_auto_min_gap: bool = False` (fallback на явне значення).

### 2.2 Дистанційний префільтр кандидатів
Після BFS/warm-start у вузлів є оцінки позицій. Якщо |Δцентрів| двох кандидатів
> `2 × розмір кадру` — не запускати LightGlue взагалі. Відсікає аліасинг полів ДО
матчингу і прискорює Phase 2. (Обережно: оцінки залежать від ланцюга — префільтр
м'який, ×2 запас, і лише коли обидва вузли ініціалізовані.)

### 2.3 Odometry-consistency (PCM-lite) замість «сусідського» кластер-гейта
Для кожного spatial-ребра (i,j): скомпонувати temporal-ланцюг i→j і порівняти
з ребром (Δцентр у px після компенсації довжини ланцюга). Неконсистентне ребро →
вага ×`inconsistency_factor` (не викидання). Це строгіша версія
`_cluster_consistency_factors` — ловить узгоджені МІЖ СОБОЮ хибні ребра
(паралельні рядки посівів), які поточний гейт пропускає.
Повний PCM (max-clique) — не потрібен на серпантинах, лишити як досліджувальний.

**Гейт:** сим-місія з вимкненим heading-hold (найбільше аліасингу): кількість хибних
spatial-ребер ↓, median_err середин ніг ↓; heading-hold-місія — без змін.

## Етап 3 — GNC-переваження як еволюція two-stage prune (прапорець, після 0–2)

Two-stage prune «рубає» ребра бінарно. GNC (graduated non-convexity) робить те саме
плавно: 3–5 раундів L2 → переваження spatial-ребер `w' = w·µ²σ²/(µ²σ²+r²)`
(Geman-McClure з GNC-розкладом µ), σ = MAD **свого класу** (урок soft_l1 враховано:
temporal не чіпаємо, пороги класо-відносні). Warm start між раундами вже є.
Конфіг: `graph_optimization.gnc_spatial: bool = False`, `gnc_rounds`, `gnc_mad_k`.

**Гейт:** реалістичний граф-тест з 10–20% хибних ребер: median_err ≤ two-stage prune,
без деградації на чистих сценах. Якщо приросту нема — лишаємо prune, етап закривається.

## Етап 4 — PCHIP-заповнення пропущених кадрів (замість лінійного)

`_fill_gaps_by_interpolation` → інтерполяція 5-DoF компонент PCHIP-ом по валідних
сусідах (та сама декомпозиція навколо центру кадру, що в `MultiAnchorCalibration`
— переиспользувати `_rebuild_interpolators`-логіку або витягнути в `affine_utils`).
Прибирає «сходинки» на дугах для реальних даних (у симуляторі дуги вже заякорені).

**Гейт:** валідатор 0.1, розріз «дуги розворотів»: err ↓, інші розрізи без змін.

## Етап 5 — Ротаційна робастність temporal-ребер (для місій без heading-hold)

При провалі temporal-матчу (зараз ребро просто випадає, дуга лишається без опори):
1. повторити матч, повернувши фічі query на кут з ланцюга `frame_poses` БД
   (він уже є зі збудови — це готовий одометричний пріор);
2. якщо ланцюг порваний — перебір k·90°.
Конфіг: `propagation.rotation_retry: bool = False`.
Досліджувальне (окремо, не в цьому плані): rotation-equivariant дескриптори
(Steerers, arXiv:2312.02152) — інваріантність без втрати дистинктивності.

**Гейт:** сим-місія без heading-hold: кількість temporal-ребер на дугах ↑,
err на дугах ↓; heading-hold-місія — без змін (retry не спрацьовує).

## Етап 6 — Одиниці та дрібне

- **cos(lat)**: метрики звітів і GSD-підказки живуть у різних метрах (Mercator vs
  справжні; ×~1.5 на 48°). Додати `mercator_scale_factor(lat)` у `coordinates.py`,
  застосувати у звітах пропагації і `ScaleManager`-підказках. На сим-даних не впливає
  (там усе в Mercator), на реальних — прибирає систематичні ~50% у «метрових» цифрах.
- Вага temporal-ребра × якість афінної проєкції H (залишок фіту 5 точок у
  `homography_to_affine` зараз викидається) — кадри з нахилом/рельєфом отримують
  меншу довіру. Прапорець, через бенчмарк.
- Видалити/підключити мертві конфіг-ключі (`anchor_weight`).

## Етап 7 — Доповнення з зовнішнього стратегічного звіту (2026-07-09)

Зовнішній звіт аналізував старий зріз коду (його головні рекомендації — factor graph,
DINOv2, відмова від SuperPoint — уже реалізовані як PoseGraphOptimizer v3.0, DINOv3-sat,
ALIKED+LightGlue). Пропозицію Lie-інтерполяції відхилено: logm сингулярний при
відносному повороті ~180° (сусідні ноги без heading-hold), кускова геодезична дає лише
C0 проти C1 у PCHIP, а рантайм використовує графову пропагацію. Корисне взято:

### 7.1 Кінематичні фактори гладкості (constant-velocity prior)
**СТАТУС 2026-07-17: реалізовано (uncommitted), flag-gated off** — `graph_optimization.kinematic_prior_weight=0.0`; трійки з α-зваженою інтерполяцією на нееквідистантних гепах (вага ~1/геп), аналітичний якобіан звірено з FD, 12 тестів у `tests/test_pose_graph_kinematic.py`. Гейт (валідатор 0.1, розріз «середини між якорями») — на Windows перед вмиканням.
Слабкі резидуали другої різниці центрів сусідніх вузлів:
`w_kin · (c[i+1] − 2·c[i] + c[i−1])` — гасять провисання середин між якорями там,
де нема loop closures. Додаткові рядки у `_residuals_vec` + якобіан; лише центри
(не кут/масштаб), вага мала відносно temporal-ребер, слоти мають бути еквідистантні
(перевірка на гепах keyframe selection — масштабувати на відстань).
Конфіг: `graph_optimization.kinematic_prior_weight: float = 0.0` (off).
**Гейт:** валідатор 0.1, розріз «середини між якорями»: err ↓; дуги без деградації.

### 7.2 SIFT+LightGlue бекенд (ротаційна інваріантність без retry)
LightGlue має офіційні SIFT-ваги; додати `sift` у `fallback_extractor`-механіку
ModelManager. Для місій без heading-hold — альтернатива/доповнення rotation-retry
(Етап 5): інваріантність на рівні дескриптора замість перебору поворотів.
**Гейт:** сим-місія без heading-hold: temporal-ребра на дугах ↑; швидкість екстракції
прийнятна (SIFT на CPU повільніший за ALIKED на GPU — міряти).

### 7.3 Dense-fallback матчер для слаботекстурних зон
При `inliers < dense_fallback_threshold` на temporal-ребрі — повторний матч щільним
матчером (LoFTR або RoMa) лише для цієї пари. Дорого (~0.1–1 с/пара) → тільки fallback,
тільки за прапорцем `propagation.dense_fallback: bool = False`.
**Гейт:** сцена з водою/однорідними полями (нова сим-місія над озером): розривів
temporal-ланцюга ↓; на звичайних місіях fallback не активується (лічильник у звіті).

### 7.4 GeM-агрегація патч-токенів DINOv3 (експеримент ретривалу)
`DINOv3Wrapper.forward_features` вже віддає `x_norm_patchtokens`; зараз глобальний
дескриптор = CLS. Варіант екстрактора: GeM-пулінг патч-токенів (+опційно PCA до 1024)
— ідея AnyLoc, пересаджена на satellite-pretrained DINOv3.
**Гейт:** окремий retrieval-бенчмарк (recall@K по GT-сусідству кадрів із сим-місій);
у пайплайн — лише якщо recall@5 покращується, бо це перебудова LanceDB-таблиць.

## Етап 8 — Запобіжники temporal-VO (сесія 2026-07-12, РЕАЛІЗОВАНО)

Контекст: lasttest (571 слот, 77 GT-якорів) — LightGlue місцями віддає 12–28 матчів
на повторюваній ріллі там, де MNN по тих самих дескрипторах бачить 100–800 пар;
MAGSAC із малої вибірки знаходить хибний консенсус → отруєні temporal-ребра, які
резидуали не бачать (апендикс 1–21 без другого якоря; бульбашка 287–297 на 9.4 км).
Деталі: CALIBRATION_DEBUG_SESSION_2026-07-11.md.

### 8.1 Санітарний гейт temporal-ребра + MNN-фолбек + skip-мости
- `vo_guards.temporal_edge_sane`: |кут| ≤ 30°, масштаб у [1/1.4, 1.4],
  |Δцентр| ≤ 1.2·діагональ·gap. Конфіг: `graph_optimization.temporal_edge_gate*`.
- `matcher.match_mnn` + `propagation.mnn_fallback`: LightGlue < min_matches →
  детермінований mutual-NN по тих самих дескрипторах.
- `propagation.skip_bridges`: розрив → міст до глибших сусідів (max_skip_frames).

### 8.2 Звірка проміжків між якорями (головний запобіжник)
- `vo_guards.check_anchor_gaps`: компонування temporal-ланцюга якір→якір
  (той самий предикт, що BFS/LOO) vs дельта якорів → ok/inconsistent/broken.
- inconsistent → `downweight_gap_edges` (вага ×0.05) ДО оптимізації;
- після неї `select_gap_fallback_frames`: кадри проміжку з відхиленням від прямої
  якір→якір > `anchor_gap_max_dev_m` (150 м) → frame_valid=0 → штатна інтерполяція.
- Конфіг: `graph_optimization.anchor_gap_check` / `anchor_gap_max_dev_m` /
  `anchor_gap_downweight`.

**Гейт:** tests/test_pose_graph_vo_guards.py (10) + регресія pose_graph зелена.
Офлайн-реплей на lasttest: max err 9456 м → 149.8 м (median 23.1 м).
Windows-бенчмарк (benchmark_propagation.py) — стандартний гейт перед мержем.
